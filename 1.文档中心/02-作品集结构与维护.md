# 作品集结构与维护

## 展示结构

首页展示 3 件精选作品：种菜农场花园消除、星盘排盘、视唱练耳听音准。首页「查看全部」及主导航「作品」进入 `/work/` 完整作品集。

完整页面按以下顺序展示：

1. 小游戏：种菜农场花园消除。
2. 小程序：星盘排盘、视唱练耳听音准、嘌呤含量查询、收纳空间、答案之书 app、息屏节拍器、热梗挑战、看看星座。
3. 公众号：神来之随笔。

星盘排盘与看看星座之间安排了其他作品。页面采用桌面两列、平板与手机单列的编辑式布局；小游戏和公众号分别使用宽幅展板。卡片使用统一纸白底、细线分隔及二维码轻抬动效，不再使用彩色背景。首页标题旁、分类概览与底部大入口共同提示完整作品数量。

首页保持有限的精选数量，完整页面负责容纳持续增加的作品。所有作品直接生成 HTML，并随构建进入全文搜索，二维码延迟加载。

## 新增与调整

1. 原始二维码保存在 `2.小程序码/`。将网页使用的标准 JPG / PNG 副本放入 `public/media/works/`。
2. 在 `src/data/works.ts` 的 `works` 数组中加入记录。`category` 使用 `game`、`miniapp` 或 `account`。
3. 同类别作品的数组顺序就是展示顺序；类别顺序固定为小游戏、小程序、公众号。
4. `featured: true` 控制是否出现在首页，建议保持 3 件左右；新增普通作品无需增加精选数量。
5. 后续添加简介时，填写 `description` 和 `englishDescription`。暂未填写时不显示简介区域。
6. 执行 `npm run build` 更新页面、分类数量、作品总数和搜索索引。

每件作品的 `id` 应保持稳定，用于页面锚点。二维码通过 `qr` 指向公开素材路径。

## 图片与二维码

十张图片均从用户压缩后的 `2.小程序码/` 原样复制到公开素材目录，不额外裁切或覆盖。公众号原始文件现已是标准 PNG。

公众号图片使用宽幅弹窗；所有作品均可放大、保存和查看原图。手机用户可保存原图后在微信中识别。

当前没有为缺少详情内容的作品创建空详情页；后续补充完整案例时，可继续扩展独立作品详情页。
